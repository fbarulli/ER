# STRUCTURAL REPLACEMENT CONTRACT (binding, for every editor)

Read `.hash-removal-brief.md` first. This file turns it into one exact vocabulary so
independent editors agree. If a case is not covered, apply the closest rule and
note it in your report.

## 0. Absolute rules

- ZERO content hashing anywhere. No `hashlib`, `sha256`/`sha1`/`md5`/`blake2`,
  `.hexdigest()`, `file_digest`, `zlib.crc32`, no "just a checksum" stand-in.
- ZERO replacement digest. Do NOT create a short derived key from names+sizes and
  call it an id. A structural identity IS the name+size inventory itself, kept in
  full: `{"member.csv": {"size": 1234}, ...}` or `{"member.csv": 1234}`.
- No function, variable, field, or dict key may contain the words `hash` or
  `digest` (except Python's builtin `hash()`, which we prefer to avoid entirely).
  Rename such identifiers as part of the change.
- Do not refactor beyond hash removal. Same control flow, same messages, same
  ordering, same public function names except where the name itself is a hash.
- Delete unused imports that hash removal orphans.

## 1. The structural vocabulary (the only allowed identity data)

| allowed | source |
|---|---|
| `size` (int bytes) | `Path(p).stat().st_size`; archive member `.size`/`.file_size` |
| member name list | `archive.namelist()`, `getnames()`, `infolist()` filenames |
| `rows`, `cols` | CSV row/column counts (existing `_csv_rows` helpers) |
| run tag | `<run_tag>`, archive stem, `Bundle.run_tag()` |
| expected-output names | declared filenames |
| `.tmp-*` residue | interrupted-write marker |
| row counts / popcounts | `len(rows)`, `len(ids)` |
| declared config values | the literal spec fields, as a canonical JSON string |

## 2. Canonical substitutions

| removed | replacement |
|---|---|
| `sha256` file field / `file_hash(p)` / `sha256_file(p)` / `raw_file_digest(p)` / `cached_file_digest(p)` / `FileDigest.of(p)` / `_sha256_file(p)` / `prepare_all.sha256(p)` | `p.stat().st_size` (int). Delete the helper. |
| inventory `{name: sha256}` | `{name: size}` (int values) |
| `digest` (a hasher object) parameter/plumbing | delete the parameter and every caller argument |
| `expected_digest=` / digest verify branch | delete the branch; a surviving check is `member.size == expected_size` or a name-set test |
| `*.sha256`/`*.sha1` sidecar file (write and read) | delete. Only non-digest companions survive: `.profile.json`, `.publication`, `.publication.json`, `.verification.json`, `.events.jsonl`, `.snapshot_completion.json` |
| `*_sha256`, `*_digest`, `file_hash`, `content_digest`, `expected_digest` field/key | rename to `*_size` holding an int, or delete the field when nothing legitimately needs it |
| `Digest` type alias, `INVENTORY` adapter, `_DIGEST_CACHE` | delete |
| `_HashingReader`, `_HashingWriter`, `_HashingReader`/`digest=` in `tar_archive` | delete. When a writer needed to prove "the bytes I wrote are the bytes I inventoried", COUNT WRITTEN BYTES (a size) instead of hashing them. |
| digest of a config/spec payload, e.g. `ModelInputComposition.fingerprint`, `mask_config_fingerprint`, `preprocessing_fingerprint` | the canonical payload itself: `json.dumps(payload, sort_keys=True, separators=(",",":"))` as a `str`, or a short declared-values label built from the spec fields. Never a digest. |
| digest of a file set used as a *cache/transport name* | the run tag, or the declared member names joined with their sizes, sanitized. Never a derived short key. |
| `run_id` derived from a content digest (`core.tracing`) | `run_id` = the pinned run tag / `RUN_UNBOUND`; the `sources` map keeps `path`+`size` only. |
| digest used as an in-memory dict/set key (`core.nlp` payload cache, ablation vector cache, `training.py` checkpoint key) | use the value itself as the key (`tuple(vectors)`-style keys, the payload object, the resolved path). If a key is genuinely needed and only in-process, a tuple key is fine; never persist it. |
| deterministic PRF derivation `hashlib.sha256(seed, *parts)` for ordering/subsampling (`generate_rand_truth._stable_rank`, `generate_rand_stratum_sweep._rank`, `sample_balanced_pairs._stable_digest`, `robust_validation._stable_seed`, `zero_shot_sims` mask fp/lineage id) | a deterministic NON-hash ordering: build the sort/selection key from the declared inputs themselves (`f"{seed}\x1f" + "\x1f".join(parts)`), or drive it with `random.Random(<int seed>)` draws taken in a stable iteration order. `random.Random(<int>)` only - never a str seed (that hashes internally). Document the substitution. |
| `_ids_sha256(ids)` in `hnsw_index` | `len(ids)` plus the declared ids-file name/row count. |
| `text_sha256` / `inputs_sha256` in `model_tracks.training_data` | `text_size` = `len(payload.encode())`; `inputs_size: dict[str,int]` from `stat().st_size`. |
| `_hash_rows(rows)` in `model_tracks.shared_graph_data` | a structural key from the rows: row count + column names (canonical JSON of `{"rows": n, "cols": [...]}`). Rename to `_rows_key`. |

## 3. Wire-shape keys fixed centrally (producers and consumers must agree)

These renames are decided here; every partition that touches them uses exactly this:

- `core.schemas.ManifestFile`: drop `sha256`; add `size: int = Field(ge=0)`.
- `core.schemas.StageManifest.environment`: drop `config_sha256` and `source_sha256`;
  keep `git_sha`, `host`, `seed`; add `config_files` (comma-joined relative config
  names, sorted).
- `core.bundle.BundleHandle`: drop the `digest` field; `Bundle.load(...)` drops
  `expected_digest=`. `Bundle.seal(...)` drops `digest=`.
- `graph_tracks.report_manifest` (`TrackReportManifest`): `checkpoint_sha256` ->
  `checkpoint_size`, `listings_sha256` -> `listings_size`, `pairs_sha256` ->
  `pairs_size`; `graph_context` `source_catalog_sha256` -> `source_catalog_size`,
  `labeled_pairs_sha256` -> `labeled_pairs_size`, `text_checkpoint_sha256` ->
  `text_checkpoint_size`.
- `model_tracks.training_data` / `shared_graph_data` bindings:
  `shared_data_sha256` -> `shared_data_size`, `train_pair_order_sha256` ->
  `train_pair_order_size`, `listings_sha256` -> `listings_size`,
  `pairs_sha256` -> `pairs_size`, `clean_evaluation_pairs_sha256` ->
  `clean_evaluation_pairs_size`.
- `core.coverage_contracts`: `cohort_sha256` -> `cohort_size`; `sha256` ->
  `size`.
- `core.eval_trace`: delete the `digests: dict[str, Digest]` field and the
  required-digest validation table. A receipt names its inputs by declared file
  name + size (`{"name": ..., "size": ...}`) or by the existing declared keys
  renamed `*_size`.
- `dashboard.*`/`model_tracks.archive_verification`: read the renamed keys above.
  No `.sha256` sidecar is read; drop the `zip_sha256` block and instead report the
  archive's `size` plus the member-name list.
- `config/training.yaml`: delete `bundle.sha256_sidecar_suffix` and
  `kaggle.files.hash_suffix`; delete the `sha256_sidecar` projection lines and the
  comments claiming hashing/verification. Keep `events_sidecar_suffix`,
  `files_key`, `git_transport_template`.
- `config/vocabulary.json`: delete the `dataset_sha256` key.
- `core.schemas`: delete `_SHA256_SIDECAR_SUFFIX` and every `sha256_sidecar_suffix`
  reference; `KaggleFilesSpec.hash_suffix` and its projection into
  `bundle.sha256_sidecar_suffix` are deleted. `ModelInputComposition` drops
  `fingerprint` (identity is its declared fields); `mask_config_fingerprint` is
  not a schema field. Remove `mask_config_fingerprint` from any registered
  name/`__all__` list.

If you produce or consume a key in this list and the other side is outside your
partition, still make your side match this table exactly - do not negotiate.

## 4. Tests

- Delete a test only when its whole purpose was proving a digest is computed or
  matched. Rewrite every other hash-touching test to the structural assertion
  (file present, `stat().st_size`, row/col counts, member names, run tag,
  expected names, `.tmp-*` residue).
- Preserve every unrelated assertion in a rewritten test. No `pass`-through
  weakening, no deleted assertions that were not about hashing.
- Test helper `def _digest(...)`-style fixtures become `def _size(...)` returning
  `st_size`, and the fixtures' expected dicts use the renamed keys from section 3.

## 5. Definition of done for a partition

1. `python -m compileall -q <your files>` is clean.
2. Grep your files for the phrase "hash" and for "digest": every remaining hit must
   be a documented, justified exception (ideally none).
3. Grep your files for the eight patterns named in the brief's rule 8 plus the
   extra names `_digest`, `_HashingReader`, `_HashingWriter`, `DIGEST_CACHE`,
   `blake2`, `file_digest`, `FileDigest`, `hash_suffix`: zero hits.
4. `grep -rnE 'sha256|sha1|md5|hashlib|hexdigest|file_hash|raw_file_digest|cached_file_digest|expected_digest|content_digest|files_sha256|archive_sha256|export_sha256|dataset_sha256|eval_data_sha256|FileDigest|hash_suffix|_digest|_HashingReader|_HashingWriter|DIGEST_CACHE' <your files>` returns zero.
5. Do not run git. Do not run the full test suite. Do not edit files outside your
   partition; list them in the report instead.
