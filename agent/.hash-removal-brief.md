# HASH REMOVAL CONTRACT (repo-wide, owner directive)

Owner rule: **never make a hash.** No content digest anywhere. Identity is
STRUCTURAL: file names + byte sizes + row/col counts + run tag + declared
member names. Nothing is fingerprinted by content.

## DELETE (definitions AND every call site)
- Any use of `hashlib` (whole import), `sha256`/`sha1`/`md5`/`blake2`, `.hexdigest()`.
- Helper definitions and their imports:
  - `core.manifest.sha256_file`
  - `core.portable_archive.raw_file_digest`, `cached_file_digest`, `_DIGEST_CACHE`, `_HashingReader`, `Digest`, `INVENTORY`
  - `core.archive_reader._HashingWriter` and the `digest=`/hashing-writer plumbing in `tar_archive`
  - `graph_tracks.data.FileDigest*`
  - `ner._sha256_file`, `ner.colab_ner._sha256_file`
  - `training.prepare_all.sha256`
- Every digest FIELD / dict KEY, including: `sha256`, `file_hash`, `files_sha256`,
  `archive_sha256`, `export_sha256`, `dataset_sha256`, `eval_data_sha256`,
  `config_sha256`, `source_sha256`, `expected_digest`, `content_digest`,
  anything ending `_digest`, and any pydantic field of a digest type.
- `.sha256` sidecar FILES: stop writing AND stop reading them. Remove
  `archive_sidecar(...)` calls whose suffix is a digest (`.sha256`, `.sha1`, ...).
- Digest-based verify paths: `verify_archive_digest`, `expected_digest=` args,
  manifest re-hash branches, receipt/receipt-mismatch checks keyed on a digest.

## KEEP, but as STRUCTURAL checks (no bytes hashed)
- file present on disk; `st_size` in bytes; CSV row/col counts; member name lists;
  run tag; expected-output name presence; `.tmp-*` interrupted-write residue check.
- `atomic_write*` and `publish_replacing` (unchanged; they are not hashes).
- `archive_sidecar` ONLY if a surviving NON-digest companion still needs it
  (e.g. `.profile.json`); otherwise delete it and `ARCHIVE_ENDINGS` if unused.
- run-tag / `uuid` generation (not a content hash). Leave those.

## RULES
1. Do NOT introduce a replacement digest under another name. No size+name "hash".
2. Builtin `hash()` for in-memory dict/set membership is OK **only if it is never
   persisted or compared as identity**. Prefer removing it too.
3. Remove imports that become unused (`hashlib`, type adapters, helpers).
4. Rewrite docstrings/comments that claim hashing/"verification"/"fingerprint";
   do not leave stale claims.
5. Otherwise behavior must be IDENTICAL. Do not refactor beyond hash removal.
6. Do NOT run git. Do NOT run the full test suite. Do NOT edit outside your partition.
   If you see a hash reference outside your files, LIST it in your report, don't touch it.
7. Compile check your files: `python -m compileall -q <files>`.
8. Grep check: your partition returns ZERO hits for
   `sha256|sha1|md5|hashlib|hexdigest|file_hash|sha256_file|raw_file_digest|cached_file_digest|expected_digest|content_digest|files_sha256|archive_sha256`
   (except `hash()` builtin if you justified keeping it).

## REPORT BACK
- files changed; symbols/fields removed; zero-hit grep proof; anything you could NOT
  remove and why; any hash reference you found outside your partition.
